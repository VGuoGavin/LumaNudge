# 测试方案与现状

显示器 DDC/CI 行为取决于硬件和连接链路；构建成功不能代替真机测试。测试前记录内屏及各外屏的原始亮度，完成后恢复。

## 手工测试矩阵

| 测试 | 步骤 | 预期 |
| --- | --- | --- |
| 只读枚举 | 运行 `--list` | 显示来源与各物理显示器；不修改亮度 |
| 初次启动 | 将外屏设为不同于来源的亮度，再启动任务 | 外屏保持原值 |
| 相对增加 | 来源亮度增加 5 个百分点 | 每台可读外屏以自己的当前值增加 5 个百分点 |
| 相对减少 | 来源亮度减少 5 个百分点 | 每台可读外屏以自己的当前值减少 5 个百分点 |
| 来源不变 | 手动调整外屏，等待超过 10 秒 | 程序不会把外屏覆盖回来源值 |
| 边界 | 在安全可见条件下测试靠近 0% 和 100% 的亮度 | 目标值被限制在 0–100%，无重复写入 |
| 拔插 | 拔掉并重新连接外屏 | 监听快速恢复；重连本身不修改亮度，下一次来源变化才调整 |
| 多屏 | 接入两台不同亮度的外屏 | 两台分别保留自身亮度差 |
| 生命周期 | 安装、暂停、继续、卸载 | 任务与快捷方式状态正确，卸载后不再运行 |

## 已验证和待验证

- x64 Windows 实机已验证构建、安装/卸载、亮度增减、保持外屏原有差值，以及来源不变时不覆盖外屏。
- 热插拔监听窗口已验证能够接收模拟设备变化消息。实际物理拔插的响应时间仍需在目标显示器与接口组合上测试。
- ARM64 已交叉编译并确认 PE 架构；尚未在 ARM64 Windows 实机运行。
- 多品牌、多扩展坞、多台同型号显示器和 0%/100% 边界尚需系统性验证。
